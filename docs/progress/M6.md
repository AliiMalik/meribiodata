# M6 — Launch

Everything between "the app works" and "the app is on Google Play".

## What shipped

| Area | State |
|---|---|
| **Premium** (D17) | Monthly subscription and lifetime unlock through Play Billing. Removes ads and the export watermark, gates no feature. Entry points: Home header, a dismissible Home card, the export screen, the last onboarding panel, and a full screen at most weekly. |
| **Create interstitial** (D16) | Capped three ways — first 2 creates free, 3 minutes apart, 4 a day. Never blocks the create. |
| **Locked templates** (D19) | Rewarded ad unlocks one template for 24 hours; Premium unlocks all of them permanently. |
| **17 templates** (D20) | 4 plain layouts plus 13 border-art designs across Classic, Geometric, Thematic and Creative. |
| **A4 only** (D18) | Letter and the 4x6 card removed. |
| **Editor → Template → Export** (D19) | Replaces an app-bar eye icon nobody found. |
| **Document text size** (#34) | Three steps of one point, on the export screen. Fonts only — never margins, so no border is breached. |
| **Plain-text share** (#35) | Copy or share the biodata as text, honouring Shareable masking. |
| **Waitlist removed** (D17) | Screen, route, form URL, strings and tests. Privacy policy at v1.2. |

## What launch still needs

**Only the owner can do these.** In order, because the first is the slowest:

1. **Payments profile** — tax details and a bank account, verified on Google's timetable. Nothing can be sold until it clears.
2. Play Console setup: Data safety, content rating, target audience, category and contact details, store listing.
3. Two products with exactly these IDs: `premium_monthly` (Subscriptions) and `premium_lifetime` (In-app products).
4. Build the bundle **with the real ad IDs**, run `python tool/verify_release.py` on it, and upload only if it passes. A bundle built without the defines ships Google's test units — it works perfectly and earns nothing, and nothing else in the toolchain will tell you.
5. Upload to internal testing → copy the **app signing** SHA-1 → create an Android OAuth client in Cloud project `meribiodata-504721`. Without this, Drive sync fails for every user but the developer.
6. Publish the OAuth consent screen.
7. 12 testers, opted in, for 14 continuous days.

**Only a real device can prove these:**

- A purchase, as a licence tester. Billing does not run on an emulator.
- Google Drive sync against a real account — unit-tested throughout, never yet run against Google.
- WhatsApp share with WhatsApp actually installed.
- NFR-2: under 3 seconds on a 3 GB phone.

## Known gaps

- **No Religious templates.** Nothing in the supplied artwork is Islamic — no geometry, no mosque motif, no calligraphy. The picker omits empty categories, so the heading simply does not appear. For this audience it is the most conspicuous absence in the collection.
- **Sindhi, Pashto and Punjabi labels are still `draft`**, awaiting a native reviewer. The export screen warns when one is selected.
- **The M0 native-reader sign-off** on Nastaliq output is still outstanding.
- **Watermark wording** is still the M3 placeholder, "Made with MeriBiodata".
- **Goldens are not enforced in CI** — they are platform-specific bitmaps, so Windows and Linux disagree. Run locally; there is a manual workflow to regenerate.
