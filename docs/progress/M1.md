# M1 — Foundation

**Shipped:** 2026-08-04

Exit criteria: project scaffold, theme + tokens, routing, DB + encryption, i18n plumbing with two
locales, CI green. All met.

## What shipped

**Scaffold.** Android-only Flutter app at the repo root (`com.meribiodata.app`, minSdk 26 pinned
explicitly rather than inherited from Flutter's default). No `ios/` target exists. Analyzer runs
`very_good_analysis` with zero issues; `dart format` is enforced.

**Design tokens.** `AppColors` is the only file allowed to hold a hex value; `AppSpacing` holds
spacing, radii and the 48dp tap-target floor. `AppTheme.lightFor(language)` builds the theme from
the active UI locale, so the font family, fallback chain and line-height come from the
`LanguageDescriptor` rather than being hardcoded. Light mode only — the dark-mode token table has
to be reviewed before implementation (§10), so it stays in M5.5.

**Contrast enforcement.** `test/theme/contrast_test.dart` computes WCAG 2.1 ratios for every pair
the app actually uses and fails CI on a regression. Two palette amendments came out of it — see
`docs/decisions.md` D5.

**Routing.** `go_router` with all eight §7 destinations wired and a redirect that gates on
onboarding completion. Screens later milestones own render an unmistakable
`MilestonePlaceholder` rather than a blank page.

**Storage.** `LocalStore` is a storage-engine-agnostic JSON document interface; `HiveLocalStore`
implements it over AES-encrypted Hive CE boxes with the key in `flutter_secure_storage`.
Verified on device: `preferences.hive` holds ciphertext.

**i18n.** ARB files for English and Urdu via `gen_l10n`, `AppL10n` generated into
`lib/l10n/generated/` (git-ignored, regenerated in CI). `LanguageDescriptor` carries all twelve
target languages with script, direction, fonts, line-heights, digit style, priority and — per D1 —
which PDF pipeline each one renders through. `AppLanguages.uiLocales` is derived from which ARB
files exist, so shipping a new language stays a data-only change.

**CI.** Three jobs: analyze + format + test (with `--fatal-infos`), a privacy guard, and a debug
APK build. The privacy guard is the NFR-1 enforcement the build prompt asks for: it fails the
build if an HTTP client appears in `pubspec.yaml` or if application code imports one.

**Tests.** 42 passing: contrast, theme typography, language registry, ARB parity (including a
check that no Urdu string is still its English source), preferences round-trip, and widget tests
covering first-run routing, locale switching and RTL layout.

## Verified on device

Pixel emulator, API 36. Onboarding → language selection → home, in both English and Urdu. The
Urdu UI is fully mirrored and renders in the bundled Noto Nastaliq Urdu.

## What surprised me

- **The specified palette has two AA failures, not one.** The build prompt predicted Secondary
  Green would fail. It does — but so does white-on-Primary-Green for button labels (3.30:1), which
  is the single most-tapped surface in the app, and Secondary Text on the Surface colour (4.34:1),
  which affects every card. Both are now measured and locked by a test rather than left to
  judgement. Details and the reversal path are in D5.

- **Inter has no Urdu glyphs, so the Urdu UI initially rendered in whatever font the device
  happened to ship.** On the emulator that looked fine, which is exactly what makes it dangerous —
  on a budget phone it could have been a Naskh face or a poor Nastaliq one, and the app's entire
  differentiator is that Urdu looks right. The theme now selects the bundled face from the
  `LanguageDescriptor`, and a test asserts it.

- **Hive encrypts values but not keys.** Confirmed by reading the box file off the device: the
  document body is ciphertext, the key `app` is plaintext in the frame header. That turns "use
  UUIDs for profile ids" from a style preference into a privacy requirement, now recorded in D2.

- **`hive_ce_generator` would have forced a prerelease `freezed`.** Its analyzer constraint is
  incompatible with every stable `freezed`. Dropping it in favour of storing JSON documents was
  better on the merits anyway — the field engine is schema-driven, so a profile's shape is data
  rather than a class — and it kept the toolchain on stable releases.

- **`flutter create` overwrites `.gitignore`.** Worth knowing before scaffolding into a repo that
  already has one.
