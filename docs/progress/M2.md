# M2 — Schema & form engine

**Shipped:** 2026-08-04

Exit criteria: default schema seeds; add/rename/reorder/hide/delete fields and sections;
repeatable groups; autosave; unit tests. All met.

## What shipped

**Domain model** (`lib/domain/biodata/`, pure Dart, no Flutter). `FieldDescriptor`,
`SectionDescriptor`, `BiodataSchema`, `BiodataProfile`, `ValidationRule` and typed values for
height, weight, currency and repeatable groups — all `freezed` + `json_serializable`, all
immutable. Enum wire formats are pinned with `@JsonValue` because they are written to disk and
will be written to `.mbd` backups.

**Schema mutations** (`schema_editor.dart`) are pure functions on `BiodataSchema`: add, rename,
reorder, hide, delete, move between sections, for both fields and sections. Illegal edits throw a
typed `SchemaException` rather than silently doing nothing. The §6.3 caps (60 fields, 10 sections,
60-character labels) are enforced here, so no UI can bypass them.

**Label resolution** (`label_resolver.dart`) implements the §6.1 order, with per-language
overrides that never overwrite each other. Shipped labels for built-in fields live in
`assets/i18n/field_labels.json` — a data asset, not ARB and not Dart, because a user running the
app in English must be able to generate an Urdu document, and a translator has to be able to
review it without reading code.

**Default schema** seeds the three mandatory sections plus a hidden extras section, with the 9.4
sensitivity defaults (Contact, Income, Address, Maslak, Date of Birth) and their masking
strategies already set — Address and DOB generalise, the rest omit.

**Form Editor** renders every field type from the schema, including repeatable groups that lead
with the "2 brothers, 1 married" shorthand and treat per-person detail as opt-in. Per-field
overflow menu: rename, mark required/optional, hide/show, mark sensitive, delete. Sensitive
fields carry a lock chip, hidden fields a crossed-eye chip, and a borrowed label a translate chip.
Autosave debounces at 600 ms and flushes on close.

**Home** lists profiles with completion, search across both the profile label and the candidate's
name, duplicate, and delete-with-confirmation. **Schema Editor** reorders sections by drag and
fields by arrows, adds fields and sections, and resets this profile to defaults.

**Tests:** 131 passing (was 99). Domain coverage is exhaustive — resolution order, every mutation,
both caps, both undeletable cases, JSON round trips, unit conversion round trips, phone shapes
Pakistani families actually write, age derivation edge cases. Plus controller tests for autosave
debouncing and flush, and widget tests for the editor.

## Verified on device

Pixel emulator, API 36. Created a biodata, typed a name, returned to the list, opened the schema
editor. Confirmed `profiles.hive` contains no plaintext: not the candidate's name, not the caste,
not even the field keys — only the profile's UUID, which is exactly what D2 says must be the case.

## Deferred

- **Caste autocomplete** — the bundled list ships at `assets/data/biradari.json` and is loaded,
  but the autocomplete UI itself is not wired up. It is a text field with suggestions pending.
- **Date display modes** (Show DOB / age / both) are modelled on the field and default to
  `dateAndAge`, but the picker for changing them is M3, where it first affects output.
- **Unit toggles** — height defaults to ft/in and weight to kg, stored canonically either way.
  The per-field toggle UI lands with Settings in M5.5.
- **9.6 boy/girl presets** — still an open question. The seed is already parameterised, so it is
  a second data table rather than new architecture.

## What surprised me

- **§6.1 contradicts itself, and it matters for output quality.** The resolution order puts "user
  override for any language" above the shipped translation, but the prose says an Urdu rename must
  not change the English document. Under the stated order, renaming a built-in field in Urdu puts
  Urdu text in the English PDF — and vice versa, English text in an Urdu biodata, which is exactly
  the blemish this product exists to avoid. Implemented as specified, with the language chip the
  spec asks for. **Recorded as D7 with a recommendation; it wants your ruling.**

- **`order` has to be per-section, and a global counter hides it.** The seed originally numbered
  fields 0..19 across the whole schema. Everything looked right — `fieldsIn()` sorts correctly
  either way on a fresh schema — until a field was moved *between* sections, where its new order
  was compared against numbers from a different range and it landed in the wrong place. Caught by
  a test, not by inspection.

- **`toJson()` was not self-contained.** Without `explicit_to_json`, json_serializable emits
  nested model *objects* rather than maps. That works when the result goes straight to
  `jsonEncode`, which falls back to calling `toJson` itself — so storage worked fine and the bug
  was invisible — but `fromJson(x.toJson())` throws. The `.mbd` backup format depends on toJson
  being self-contained, so this would have surfaced in M5 as a mysterious restore failure. Fixed
  with `build.yaml`.

- **Two bugs only showed up on the device.** The Home list held its first load forever, so
  returning from the editor still showed "Untitled biodata / 0% complete" after the form had been
  filled in — every test passed, and the screenshot did not. And the editor's flush-on-dispose
  raced its own `notifyListeners`, which would have thrown after the widget was gone. Both now
  have regression tests.

- **The D2 rule about Hive keys earned its keep immediately.** `profiles.hive` shows the UUID key
  in plaintext next to fully encrypted values. Had profile ids been derived from the candidate's
  name, every name would be sitting readable on disk under an app whose entire promise is that it
  is not.

- **Two things in §6.2's field table are not fields.** "Profile Name" is never printed, and the
  optional Header renders outside the section layout. Both are modelled as properties of the
  profile instead, so templates never have to special-case a field that must not appear.
